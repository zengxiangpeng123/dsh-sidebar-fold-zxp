# 插件列表：排序与可折叠分组 —— 设计（短）

日期：2026-10-28　|　规模：**中等**（客户端 + 新增宿主设置）
状态：**待批准**

## 意图与原因

现在那排插件入口是「一个插件一行、顺序由各插件自定」，装到八个之后：**找不到**（顺序没有逻辑）、**占地方**（每行 46px）。折叠插件已经解决了「一次全收起」，但收起来之后你还是得展开、还是得在无序列表里找。

所以再加两层：**按你定的顺序排** + **按你定的组归类，每组可折叠**。

## 目标

- 侧栏呈现为若干组：`常用 (2) ▸` / `开发 (3) ▸`，点组标题展开该组
- 组内顺序、组间顺序、哪个插件归哪组，全部由你决定
- 所有编辑在 **设置 → 插件列表** 里完成（上移/下移、改组名、加组、删组）
- 配置存在宿主侧（跨浏览器一致、可导出）
- 没配置过的插件自动落到「未分组」，不丢、不藏

## 非目标

- 不在侧栏里做拖拽（见约束 2）
- 不改变插件本身的行为、图标、点击结果
- 不做标签、搜索、多选
- 不接管整个左列（不顶替 `sidebar` 槽）

## 反目标

- 组标题被外壳重渲染冲掉，闪一下就没了
- 折叠组时把「当前正在看的那个面板」也藏了
- 配置里出现已卸载插件的 id → 变成幽灵组、或让整份配置失效
- 排序与外层「插件列表」折叠互相打架（收起时还冒出组标题）

## 约束（已核实）

1. 外壳按各插件注册的 `order` 渲染 `nav > button`，**注册顺序改不了**；排序只能在我这层用 CSS `order` 做（不动 DOM 节点，否则会和 React 冲突）。
2. 在侧栏拖拽 = 直接移动外壳管理的节点，一次重渲染就复原，还可能抛错。所以编辑放设置页。
3. 组标题必须由**我自己的节点**画，插入外壳的 `nav` 里；外壳重渲染时可能被清掉 → 需要 `MutationObserver` 补回。
4. 行元素带 `display:flex` 类样式，隐藏必须用内联 `style.display`（`hidden` 属性会被类规则盖掉）。
5. 每个条目有稳定的 id（`entries` 槽元数据里能拿到），这一 id 就是配置的键。

## 已决定（我方裁定，可推翻）

1. **排序用 CSS `order`**：行赋整数（组序号 × 1000 + 组内序号 × 10），组标题赋（组序号 × 1000 - 5）。整个 `nav` 设为纵向 flex。
2. **组标题是我的节点**：一个 `button`，结构模仿原生行（同样的内边距、字号、hover），带组名 + 计数 + 折叠箭头。观察 `nav` 的 `childList`，标题不见就补回。
3. **两层折叠各管各的**：外层「插件列表」收起时，**组标题也一起收**（只留开关行 + 当前面板行）；展开后各组按自己的折叠状态显示。
4. **当前打开的面板始终可见**：即使它所在的组被折叠，也把它露出来（否则你不知道自己在看什么）——沿用现有规则并扩展到组层。
5. **配置存宿主**：`~/.dsh/dsh-sidebar-fold-zxp/settings.json`，结构 `{version, groups:[{id,name,collapsed}], items:{<entryId>: {group, order}}}`；客户端启动拉一次、每次保存 PUT 一次。
6. **未配置的插件**：归到「未分组」组，排在最后，按条目 id 排序——保证稳定，不会每次刷新乱跳。
7. **幽灵条目**：配置里有、但槽位里已不存在的 id，设置页显示为「已卸载」并可一键清理；不参与渲染，也不影响其它条目。

## 留给实现者

- 组标题的视觉（和原生行多像）
- 默认组的名字（建议「插件」）
- 设置页里「上移/下移」是否需要键盘支持

## 验收

1. 设置里把两个插件归到「常用」、调整顺序 → 侧栏立刻按新顺序分组显示
2. 点组标题 → 该组收起/展开；刷新后保持
3. 外层「插件列表」收起 → 组标题一起消失，只剩开关行（+ 当前面板行）
4. 当前打开「任务看板」→ 即使它所在组被折叠，那一行仍可见
5. 卸载某个已分组的插件 → 设置页把它标为「已卸载」，侧栏不出现空组
6. 装一个新插件 → 落进「未分组」，不打断已有排序
7. 把 settings.json 改成坏 JSON → 插件回落到「全部未分组」，不崩、不白屏
