# 设计说明

## 要解决什么

DSH 的 `sidebar.panellist` 是一个**列表槽**：每个带入口的插件注册一条，外壳用 `panels.map()` 一行一行画出来，每行约 46px。装到七八个之后，这排入口吃掉左栏三分之一的高度，下面的工作区/会话列表被压得只剩一点。

外壳**没有**任何折叠、溢出或隐藏他人的机制，`layout` 服务也没有隐藏面板的接口。所以这件事只能由插件在浏览器侧自己做。

## 目标

- 一整块可以一键收起
- 条目可以按组归类，每组可以单独收起
- 组内顺序、组间顺序、条目归哪个组，都由用户决定
- 卸载后左栏完全恢复原样

非目标：不改插件行为、不改图标、不接管整个左栏（不顶替 `sidebar` 槽）。

## 三个硬约束

1. **行是 React 渲染的**。移动节点会被下一次渲染复原，还可能抛错；能改的只有样式。
2. **行上的类设了 `display: flex`**，会盖掉浏览器对 `[hidden]` 的默认样式——用 `hidden` 属性写代码看起来对，屏幕上什么都不变。
3. **不能读别人的注册表**。原计划用 `ctx.slots.entriesOfSlot('sidebar.panellist')` 枚举条目，但桌面端的外壳是另一份构建，它的 `slots` 只暴露 `register` / `inject` / `registerFactory`，枚举返回空。浏览器那份有，桌面端没有——**同一个插件在两端行为不同**，而且不报错。

## 最终方案

**排序**：给行写 CSS `order`（组序号 × 1000 + 组内序号 × 10），组标题写（组序号 × 1000 − 5）。React 感知不到，重渲染不影响。

**隐藏**：写内联 `display`；折叠全部则写成一条 `html[data-fold-collapsed="true"]` 下的规则。

**组标题**：本插件创建的 `<button>`，插进外壳的 `nav`；`MutationObserver` 盯着 `childList`，被冲掉就补回。点它在**捕获阶段**拦下并 `stopPropagation`——外壳的 row 处理器会拿本插件的 id 去 `selectPanel`，而它没有对应面板。

**条目标识**：行自己的 `aria-label`。这是两端都有、且稳定的唯一标识。重名时加 `#2` 后缀。

**状态**：分组与顺序存宿主（`~/.dsh/dsh-sidebar-fold-zxp/settings.json`，原子写）；折叠状态先写本地再往宿主保存，保存失败不影响已经发生的交互。

**排序规则**是纯函数，在 `src/plan.js` 与 `src/edits.js`，`node --test` 覆盖；浏览器半只把返回的数字写进样式，自己不算任何东西。

## 走过的两条死路（写给未来的自己）

**一、把它当成「读数据再改节点」。** 前半段靠注册表拿条目列表，在桌面端永远是空数组，于是整块功能静默失效。表现是「装了、行也在、就是什么都不发生」。最终改成从 DOM 读 `aria-label`。

**二、改成纯 CSS 键控 `[aria-label=…]`。** 这一步理念上更稳（React 不会碰样式表），但当时没有解决「组标题得由插件自己画」的问题，所以只能提供显示/隐藏，做不出分组。

## 一个不是代码的坑

客户端插件按 `/plugins/…/client.js?rev=<文件元数据哈希>` 加载，响应头是 `immutable`、缓存一年。**桌面端不彻底退出进程就不会换代码**——刷新页面没用。改完这个插件必须完全退出再打开，否则看到的是旧版本，而且没有任何提示。这一条耗掉了整个晚上大半的时间。
